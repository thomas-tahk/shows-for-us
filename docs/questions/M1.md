# M1 — interpretations and calls made during the cloud build (2026-10-26)

One line each: issue · the call · what it affects.

- all · the repo's specialists (`.claude/agents/*.md`) are not registered as agent types in the cloud session, so each worker ran as a general-purpose agent told to read and follow its specialist file, on the model that file names · nothing user-facing
- all · the cloud container's network policy blocks query.wikidata.org, en.wikipedia.org and WebFetch; using GitHub Actions to fetch for the session was refused as a containment escape · no live Wikidata/Wikipedia data in this build; live pull is the owner's step
- #6 · no-key response is `200 {"events": [], "reason": "..."}` (the issue's "200 [] plus a reason field" can't be a bare array) · the show page reads `events`
- #6 · cache `public, max-age=300, s-maxage=900` (15 min at the edge), errors and no-key `no-store` · tighter than the ≤1 h ceiling, to stay well inside Ticketmaster's "reasonable periods"
- #6 · Ticketmaster query: keyword = show title, `classificationName=Theatre`, `countryCode=US`, upcoming only, first 50; event kept only if its name contains the title as a whole word · non-US dates and events named differently (e.g. "Hamilton (Touring)" is fine, "An Evening of Hamilton songs" also passes) — matching on Ticketmaster attraction IDs is the better long-term fix
- #6 · a Ticketmaster failure returns 502 `{error}` without the upstream body (could contain the key) · show page shows "live dates unavailable"
- #3 · the 15 flagships (Tony Best Musical / Pulitzer winners believed running or touring): hamilton, les-miserables, the-lion-king, rent, the-book-of-mormon, hadestown, kimberly-akimbo, the-outsiders, maybe-happy-ending, jersey-boys, kinky-boots, the-phantom-of-the-opera, dear-evan-hansen, next-to-normal, a-strange-loop · "currently running" is from model knowledge, unchecked; Rent, Kinky Boots, Next to Normal are the doubtful ones — swap any in `frontend/data/flagships.json`
- #3 · only Hamilton and Les Mis carry Q-ids; the other 13 are found at pull time from their English Wikipedia article title (exact match) · a wrong title fails that one show loudly
- #3 · fixtures for Hamilton/Les Mis are hand-built in the API shapes (people Q-ids, Commons files and Wikipedia extracts are placeholders); the committed `data/shows.json` is built offline from them (2 shows, `meta.live: false`) · the site shows placeholder data until the owner runs `npm run pull -- --record` once
- #3 · Les Mis merges the French original + English version items, English credits preferred per role, falling back to the original · e.g. composer from the original, lyricists Kretzmer/Fenton from the English item
- #3 · IBDB show link format `https://www.ibdb.com/broadway-show/<P1219>` taken from a wiki template's docs, not Wikidata's own formatter · check on the first live run
- #3 · a live run with any failed show writes `data/shows.partial.json` instead and exits 1, so a broken weekly refresh never replaces good data
- #8 · weekly refresh runs Mondays 06:17 UTC, opens a `data-refresh` PR only when show data changed (timestamp-only changes dropped), runs typecheck/test/build itself because bot-made PRs get no CI · a failed pull = red run, no PR, data untouched

- #4 · write-ups drafted from model knowledge because no source could be opened; every fact cites the show's Wikipedia article, every file has `sources_opened: false` + `status: awaiting-owner-check`; `runs: []` everywhere (official sites unreadable); official ticket URL only where confident (6 of 15) · the owner's spot-check is the real source check
